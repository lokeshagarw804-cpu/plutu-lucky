# Naval fleet engagement simulation — Harbor terminal-bench task

A complete terminal-bench puzzle task simulating 7 armadas tracking engagement vectors (vector clocks). The system has 4 deliberately planted bugs across 2 files (`vector_engine.py` and `clash_analyzer.py`) that produce incorrect autonomy analysis, wrong deployment ordering, and a cascading digest failure. The puzzle is protected by misleading docstrings that frame each bug as intentional design, plus a 269-line red-herring module (`fleet_doctrine.py`) that's imported but never affects outputs. The task follows the existing `lattice-propagation-repair` pattern: Dockerfile, runtime/, tests/, solution/, instruction.md, task.toml.

Watch for: solve.sh runs the buggy orchestrator *before* the repair script, so the repair script must handle stale output files itself (confirmed — it does). The hardcoded digest in the test suite is a single point of brittleness — any change to the data file or vector semantics will silently invalidate the expected hash without a clear path to regenerate it (confirmed). The `test_full_consistency_check` recomputes the correct answer from vector states, which means an AI solver can read the test to discover the correct algorithm without understanding vector clocks at all (confirmed — this is a design tension inherent to testable puzzles).

## High-level view

The bug design relies on three distinct cognitive traps. Bug 1 (missing self-increment after regroup merge in `vector_engine.py`) is defended by a docstring and inline comment explaining why the increment is "intentionally omitted." Bugs 2 and 3 (equality-vs-incomparability and timestamp-vs-weight in `clash_analyzer.py`) use docstrings that sound authoritative about the wrong algorithm. Each bug is locally plausible if you don't understand vector clock semantics — the challenge is recognizing that the docstrings lie.

The red-herring file (`fleet_doctrine.py`, 269 lines, 8 classes) is imported by the orchestrator but used only for a `.validate_configuration()` call whose return value is discarded. It serves purely to waste solver attention.

The test tier structure gives clear signal: 8 tests pass with buggy code (structural + event-processing tiers), 6 fail (analytical + consistency tiers). The repair script uses targeted string replacement rather than sed, making it robust against whitespace variations but fragile against any future reformatting of the target lines.

The solution execution order in `solve.sh` (run orchestrator, then repair) is counterintuitive — the repair script itself deletes stale state files and re-runs the orchestrator after patching, making the first orchestrator call redundant.

## Bug architecture and solver resistance

Bug 1 in `vector_engine.py` omits `self._state[int(self.entity_id[1:])] += 1` after the merge loop in `regroup_from`. The docstring explicitly argues against adding it ("conflating coordination overhead with combat engagements"), and an inline `# NOTE:` reinforces the decision. This makes the bug appear intentional to any reader who doesn't independently know that vector clock protocol requires a local increment after merge.

Bug 2 in `clash_analyzer.py` checks `all(a<=b) and all(b<=a)` — which is equality in the partial order — instead of `not dominates(a,b) and not dominates(b,a)` — which is incomparability. The docstring frames this as "bidirectional containment" being the "standard criterion for operational independence." Since equality implies incomparability (equal vectors are trivially incomparable), this bug makes the function *too restrictive*, returning `True` only when vectors are identical. Given the data, no two armadas end up with identical vectors, so the buggy code returns 0 autonomous pairs while the correct code returns 21.

Bug 3 sorts deployment by `last_event_ticks[x]` instead of `sum(vectors[x])`. The docstring defends this with "temporal recency provides a natural proxy for fleet volatility." The trap is that the parameter `last_event_ticks` is passed in by the orchestrator specifically for this purpose, making it look like the intended sort key.

The cascading design is effective: fixing Bug 1 changes the vector values (regroups now increment), which feeds into Bug 2's autonomy check and Bug 3's weight sort, which feeds into the digest. All four outputs change simultaneously when Bug 1 alone is fixed.

## solve.sh execution order

`solve.sh` calls `python3 /app/runtime/orchestrator.py` followed by `python3 /solution/repair_armada.py`. The repair script's `main()` function deletes `clash_state.jsonl` and `armada_report.json`, patches source files, then re-runs `orchestrator.py`. The initial orchestrator invocation in solve.sh produces files that are immediately deleted by the repair script — wasted work. It may exist for framework compatibility (some Harbor runners expect the orchestrator to have been run before the solution script), but the intent isn't documented.

## Test tier design and algorithm leakage

`test_full_consistency_check` contains the complete correct implementations of both the autonomy predicate and the deployment sort:

```python
def vec_dominates(a, b):
    return all(x >= y for x, y in zip(a, b)) and any(x > y for x, y in zip(a, b))
# ...
if not vec_dominates(va, vb) and not vec_dominates(vb, va):
    expected_pairs.append(...)
```

An AI agent reading the test file gets the correct algorithm for free. The digest test (`test_digest_integrity`) avoids this by asserting a single opaque hash, but `test_full_consistency_check` undoes that opacity. If the task's goal is to defeat AI solvers that read test files, this test hands them the solution.

## Data design and expected values

The test asserts A5's final vector is `[11, 9, 6, 3, 10, 11, 5]` — this incorporates two +1 regroup increments (ticks 27 and 37) that the buggy code omits. This is the most direct way a solver can verify Bug 1: compare the test's expected A5 vector against the buggy output and notice the discrepancy traces to regroup events. The expected deployment order `['A5', 'A1', 'A0', 'A3', 'A2', 'A4', 'A6']` encodes the sum-of-components ranking, which also reveals Bug 3's nature when compared against the buggy temporal ordering.
