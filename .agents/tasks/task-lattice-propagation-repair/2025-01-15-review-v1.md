# Lattice propagation repair: t-bench task replacement

A new "hard" debugging task replaces the old `spatial-index-repair` challenge. The task embeds 7 mathematically subtle bugs across 4 files in a lattice signal propagation simulator (wave attenuation, phasor interference, DFS path enumeration, digital filter pre-warping, and time quantization). A repair script patches all 7 via string replacement, and 20 pytest assertions validate the fixed output. The red-herring surface area is large: Doppler compensation, spectral leakage, Goertzel, jitter statistics, SCC detection, and cascade composition are all present and correct.

**Watch for:** the DFS visited-set bug's repair relies on exact string matching that breaks if whitespace or comments change (confirmed); test tolerances for interference (±0.05) may admit partially-fixed states without CI verification (likely); no downloadable zip/tarball archive is generated for task distribution (confirmed).

## High-level view

The task topology is a 7-node directed graph with cycles (5→2→1, 5→2→4→6), requiring DFS backtracking correctness to enumerate all 14 simple paths from sources to node 6. The 7 bugs span propagation_core (log-base, phase wraparound), lattice_analysis (sin/cos swap, boundary normalization), topology_resolver (visited-set leak), signal_filter (Nyquist denominator), and calibration (floor vs round). Each bug individually produces wrong-but-plausible output; together they form a cascade where the test assertions cannot pass unless all 7 are fixed. The repair script uses exact string-match patching, which is the standard approach for t-bench solutions but means the buggy code's formatting is load-bearing.

The test harness validates 20 assertions across path count, propagation delays, per-node energy (7 nodes), interference magnitudes (6 nodes checked), and resonance detection. Tolerances vary: delays get 1e-6, energies get ±0.01, interference gets ±0.05.

The `instruction.md` deliberately withholds any hint about which modules or what kind of bugs are present, giving only the system architecture description and the command to run the pipeline.

## Bug interaction design

The 7 bugs interact through the pipeline: log-base mismatch (bug 1) corrupts attenuation, feeding into energy and interference. Phase wraparound (bug 2) and sin/cos swap (bug 3) compound in phasor addition. The DFS bug (bug 5) reduces path count, changing how many signals arrive at nodes. The filter bug (bug 6) shifts the passband, altering energy levels. The quantization bug (bug 7) changes which signals land in the same time bin for interference.

A solver who fixes only the DFS bug sees path count change from ~10 to 14, but interference/energy remain wrong. A solver who fixes only the phasor bugs sees magnitudes change but still fail because attenuation and path count are wrong. The test assertions are calibrated to the all-fixed state, so partial repairs don't accidentally pass.

## DFS visited-set semantics

The early-return optimization in `topology_resolver.py`:

```python
if len(neighbors) == 1 and neighbors[0] == target:
    paths.append(current_path + [target])
    return  # BUG: missing visited.discard(node)
```

When this fires, the node remains in `visited`, preventing sibling branches in the caller's loop from passing through this node. In the given topology, node 5 has edges to nodes 2 and 6. When exploring 0→3→5 with target=6, the filtered neighbors of node 5 might be `[6]` (if 2 is visited), triggering the shortcut. Node 5 stays in `visited`, blocking any other path that would transit through 5.

Note: the shortcut and the general loop can both try `target` from the same node, but `target` is never added to `visited` so the general loop's attempt just appends a duplicate path — except it doesn't fire here because when the shortcut triggers, it returns before the loop executes. This was confirmed correct by the path count test expecting exactly 14.

## Filter pre-warping error

```python
omega_low = 2.0 * math.pi * freq_low / sampling_rate       # BUG
omega_high = 2.0 * math.pi * freq_high / sampling_rate     # BUG
```

The bilinear transform pre-warping formula should normalize by Nyquist (`sampling_rate / 2`), not by `sampling_rate`. With `sampling_rate=1000` and `freq_low=50`, the buggy code gives `omega_low = 0.314` when it should be `0.628`. This shifts the effective passband down, attenuating energy in the 50–200 Hz band where the test signals live.

## Boundary normalization in energy computation

In `compute_node_energy`, the final window is shorter than `window_size` when signal length isn't a perfect multiple:

```python
energy = math.sqrt(sum(s ** 2 for s in window) / window_size)  # BUG
```

Dividing by the full `window_size` when `len(window) < window_size` deflates the boundary window's energy. With `window_size=64` and `num_samples=500`, the last few windows are truncated, biasing the average energy downward.

## Missing downloadable archive

The old task had `spatial-index-repair.zip` tracked in the repository. The new task has no zip or tarball checked in — only the `.gitignore` entry for `lattice-propagation-repair.tar.gz`. If the t-bench infrastructure expects a downloadable archive for task distribution, a build/release step or checked-in artifact is needed.
